# Decision Log

> 이 파일은 Korea Trend Dashboard의 주요 설계 결정을 ADR(고유 참조 번호, 날짜, 제목, 상태, 문맥, 결정, 근거, 결과) 형식으로 기록합니다.
>
> **상태 체계:** `accepted` / `superseded` / `rejected`
> - `accepted`: 실제 저장소 코드·문서·대화로 승인 깰성이 확인된 결정
> - `superseded`: 후속 결정으로 대체된 결정
> - `rejected`: 명시적으로 거부된 결정
>
> 승인 근거가 없는 제안은 accepted로 등록하지 않는다.

---

## ADR-001: 프로젝트 목적과 범위

- **날짜:** 날짜 확인 필요 (Git 기록에서 명시적 승인 날짜 확인 불가)
- **상태:** `accepted`
- **근거:** `AGENTS.md` 문서에 구체적으로 명시됨 — 저장소 코드와 문서 전반에 관슬됨
- **문맥:** 프로젝트 목적과 담당 AI의 허용 범위를 명확히 할 필요가 있었다.
- **결정:** Korea Trend Dashboard는 한국 트렌드 레이더다. 투자·사업 의사결정 도구가 아니다.
- **결과:** 작업 지시와 문서에 일관되게 반영해야 한다.

## ADR-002: RSS 뉴스 헤드라인 기반 후보 발갬

- **날짜:** 날짜 확인 필요 (Git 기록에서 명시적 승인 날짜 확인 불가)
- **상태:** `accepted`
- **근거:** `.github/workflows/collect.yml`, `config/feeds.yaml`, `radar/` 코드에서 실제 구현됨
- **문맥:** 트렌드 신호를 얻기 위한 데이터 소스를 선정해야 했다.
- **결정:** RSS 뉴스 헤드라인에서 키워드를 추출해 일일 집계한다.
- **결과:** YouTube, 네이버 실시간 검색어 등은 이 결정을 조건으로 전달된 데이터에 의존한다.

## ADR-003: 데이터 보존 및 덮어쓰기 방지

- **날짜:** 날짜 확인 필요 (Git 기록에서 명시적 승인 날짜 확인 불가)
- **상태:** `accepted`
- **근거:** `AGENTS.md` "데이터와 수집 보호" 섹션에 명시, `data/` 디렉토리 구조로 확인됨
- **문맥:** 누적된 데이터의 무결성이 필요했다.
- **결정:** `data/` 내 파일은 승인 없이 재생성·삭제·덮어쓰기 금지.
- **결과:** 반드시 PR 승인 후 `data/` 변경이 가능하다.

## ADR-004: RSS 감사의 수동·읽기 전용 운영

- **날짜:** 날짜 확인 필요 (Git 기록에서 명시적 승인 날짜 확인 불가)
- **상태:** `accepted`
- **근거:** `AGENTS.md` "RSS 감사 도구" 섹션, `.github/workflows/audit.yml` 수동 트리거로 확인
- **문맥:** 감사가 우돈히 수집 데이터를 변경할 위험이 있었다.

- **결과:** 감사는 반드시 수동 트리거. 수집 워크플로에 접근하지 않는다.

## ADR-005: YouTube 정책 제약에 따른 기능 제한

- **날짜:** 날짜 확인 필요 (Git 기록에서 명시적 승인 날짜 확인 불가)
- **상태:** `accepted`
- **근거:** `AGENTS.md` "YouTube 관련 경계" 섹션에 상세히 명시, 해당 문서를 통해 승인된 것으로 오는날 기준 확인
- **문맥:** YouTube Data API 정책이 복잡하고 데이터 보관·미표시에 제약이 있었다.
- **결정:** YouTube Data API는 별도 승인된 설계·정책 검토 전까지 구현하지 않는다.
- **결과:** 승인된 설계 없이 YouTube 관련 코드를 추가하지 않는다.

## ADR-006: AI 협업 및 PR 승인 절차

- **날짜:** 날짜 확인 필요 (Git 기록에서 명시적 승인 날짜 확인 불가)
- **상태:** `accepted`
- **근거:** `AGENTS.md` "절대 원칙" 6번 항목에 명시, 실제 모든 변경이 PR 통해 진행된 것으로 Git 기록 확인
- **문맥:** 여러 AI 에이전트가 협업하는 환경에서 승인 채널이 필요했다.
- **결정:** `main` 직접 push 금지. 별도 브랜치와 PR 사용. 자동 merge 금지.
- **결과:** 모든 변경에 사용자 승인이 필요하다.
