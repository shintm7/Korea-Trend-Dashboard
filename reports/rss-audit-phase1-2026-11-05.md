## 발견한 점

1. **두 목록 모두 식음료·뷰티·여행·육아·반려·라이프스타일 전문 매체가 사실상 없다.** 이 프로젝트의 목적(소비 트렌드 선행 포착)에서 가장 중요한 공백이다. 웹 검색으로는 쓸 만한 RSS 목록을 찾지 못했다. 이 분야는 별도 조사가 필요하다 (추정으로 URL을 만들지 않는다).
2. **스포츠·연예 피드(4개)를 더 넣으면 이미 두드러진 스포츠 쏠림이 커질 수 있다.** 확장 우선순위에서 뒤로 둔다.
3. **`인터넷·시사` 계열은 정치 비중이 높아** 정치 필터로 많이 걸러질 것이다(수집 효율이 낮다).
4. **자료 간 불일치**: 국민일보는 newswatcher 에서 ✅(8/20)인데 우리는 10/31 점검 후 비활성으로 뒀다. 세계일보는 gist(3/16)에서 폐지로 적혔지만 우리 쪽에서는 작동 중이다. 두 자료 모두 우리 직접 측정보다 우선하지 않는다.
5. **`allArticle.xml` 형식 피드가 약 40개**로 같은 CMS 계열이다. 파싱은 균일하지만 같은 업체 CMS 의존이라 한 번의 정책 변경이 여러 피드에 동시에 영향을 줄 수 있다.
6. gist 가 제안한 **Google News `site:` 검색 RSS** 는 제목·링크만 제공하고 자동 수집 이용 조건을 확인하지 못했다. 이용 조건을 원문으로 읽기 전에는 채택하지 않는다.

## 2단계 제안 (Actions 수동 실행, 코드는 별도 승인)

`audit.yml`(수동) + `scripts/audit_candidates.py` 를 새로 만들어 한 번 실행한다. 수집 파이프라인과 데이터는 건드리지 않는다.

1. 후보 73개와 현재 활성 62개를 모두 요청: HTTP 상태, robots.txt 허용 여부, XML 파싱, 기사 수, 최신 기사 시각, 시각대 어긋남 의심(`naive_kst`)
2. **기사 중복률**: 후보 피드 제목을 정규화 해시로 현재 62개 피드 제목과 비교(메모리에서만 계산). 헤드라인 원문은 저장·출력하지 않는다.
3. **새 주제 기여도**: 후보 피드에서만 나오는 키워드 수와 기존 62개에서도 나오는 비율. 새 피드가 새 주제를 얼마나 가져오는지가 핵심 지표다.
4. 결과를 매체별·분야별 표로 출력하고, "추가 / 보류 / 제외" 분류안을 만든다. **추가는 사용자 승인 후**에만 `feeds.yaml` 에 반영한다.

기존 데이터와의 비교 가능성 때문에, 소스 변경은 기준선(21일)이 쌓이기 전에 하는 편이 낫다. 추가 시점은 `days.csv` 에 기록해 기준선 해석에 쓴다.
